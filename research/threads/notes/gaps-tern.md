### Deliberately avoided

- **A second UI transport for native PTY programs:** TSP stays in-band so SSH, ordering and daemon replay follow the existing terminal stream. This avoids needing a parallel socket for that use case. Houston's decided structured-provider adapters remain a different architecture; importing TSP is not necessary to adopt its lifecycle lessons. [Transport](https://docs.stencil.so/tern/protocol/transport.html).
- **Program-driven layout measurement and animation ticks:** programs describe semantic state; Tern owns layout and clocks motion. This removes resize/redraw work and per-frame spinner traffic from the program. Keep Houston thread updates event-driven and local animations visibility-aware. [Protocol overview](https://docs.stencil.so/tern/protocol/index.html).
- **Immutable historical screen rows as the native content model:** Tern keeps live history addressable by ID, allowing updates offscreen. Houston's turn-fold/work-log design should preserve late tool and child updates rather than finalizing rows too early. [Protocol overview](https://docs.stencil.so/tern/protocol/index.html).
- **Executing arbitrary scripts or raw HTML in program surfaces:** the constrained vocabulary and scoped styles keep supplied content inside its pane. Houston should adopt that boundary for rich thread rendering. [Surface security](https://docs.stencil.so/tern/protocol/operations.html).
- **Plugin capability prompts/signing:** Tern deliberately trusts installed plugins as user code because useful terminal plugins already need broad file/process/shell access. This is separate from agent tool approvals; it does not justify bypassing Houston's provider approval or keychain policies. [Trust model](https://docs.stencil.so/tern/concepts/security.html).
- **A separate native agent runtime just for its GUI — inference:** omp keeps its agent/editor state machine and ANSI fallback while Tern supplies rendering. That avoids runtime replacement for the native view itself. Whether Tern deliberately rejected Houston-style Thread/Terminal conversion is **unverified**; no sourced rejection of Houston's grid model, terminal excerpts, parent-first escalation or ACP approach was found. [Protocol ownership](https://docs.stencil.so/tern/protocol/index.html), [fallback](https://docs.stencil.so/tern/protocol/handshake.html).

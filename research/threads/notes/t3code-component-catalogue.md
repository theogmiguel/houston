No clone, installation, app launch, or other local file creation was performed.

This expands the earlier `t3code-thread-ui.md`; routine toolbar/sidebar/diff-panel inventory is not repeated. It follows the **web** thread renderer. Paths and lines refer to this pinned snapshot, which is newer than the earlier inventory. A source link is `https://github.com/pingdotgg/t3code/blob/74dfbb697235b0db87355d3f8575dc2ba45dddf7/<path>#L<line>`.

There are **24 contract turn-item types** and six top-level timeline entry kinds: `message`, `proposed-plan`, `html-render`, `mcp-app`, `work`, `event`. Presentation adds working/thinking rows, tool disclosures, turn/attempt folds, compaction rows and worktree-setup rows. Reads, image operations, browser/device actions, MCP calls and most orchestration operations are **presentations of generic tools**, not additional contract types. `todo_list` and `checkpoint` are explicitly filtered from the ordinary timeline (`apps/web/src/session-logic.ts:627`); inspector support does not establish visibility.

“Common item data” means IDs for item/thread/run/node/provider thread/provider turn/native reference/parent item, ordinal, title, status, started/completed/updated timestamps, and optional tool nonexecution kind, surface, icon and source (`packages/contracts/src/orchestrationV2.ts:1322`). Projected rows additionally carry source thread/item identity and local/inherited/synthetic visibility (`:1616`). “S” means contract states `idle/pending/running/waiting/completed/failed/cancelled/interrupted`; work rows map the three active states to `inProgress`, cancelled/interrupted to `stopped`, and preserve completed/failed/idle (`apps/web/src/session-logic.ts:356`). **Declined** is a presentation/approval/secret outcome, not a ninth turn-item status. “Tool detail” means foreground input/arguments, muted result, images if present, and lazy fetch of omitted output on disclosure. Its exact fixed copy is “Loading output…”, “Couldn't load output: ${error}”, “Output is no longer available.”, “No output.” and image alt “Tool output image” (`apps/web/src/components/chat/V2ItemInspector.tsx:106`, `:143`). Blank/absent fields do not manufacture labels or disclosures. Copy in quotes is literal; `${…}` is a dynamic template. Provider prose, question labels, model names and arbitrary tool names are data, not fixed UI copy.

No separate V2 `file_read`, `image_generation`, `image_view`, `rate_limit`, `provider_status`, browser/device/PR action, native-goal or agent-message discriminator was found; actual representations are identified above.
- Normal filtering is decisive: `todo_list` and `checkpoint` are skipped; synthetic Preparing workspace commands and cancelled workspace-preparation errors are skipped too. Inspector/generic event fallback support is catalogued without claiming default visibility. Handoff/fork/interrupt/subagent use V2LifecycleRow; compaction uses its special row; thread_created commonly enters work and can become a resource-summary card.
- This is source inspection of the current web client, without runtime visual/interaction testing. Mobile/native clients and provider adapters can differ. Visibility depends on scopes, capabilities, flags, settings, density and viewport. This does not prove every state can be triggered with every provider.
- Summary vs raw reasoning is not a two-field contract or verified selector: the provider supplies one text field. No dedicated literal Thought for Xs rendering was found; work-turn, live-turn, task and subagent durations were verified.
- Arbitrary tools and App content are open-ended. The catalogue exhausts known component/contract discriminators and all 81 fixed T3 MCP presentations, not every label a third-party tool/App could produce. Tool-specific argument schemas, provider image-generation vocabulary, hosted App UI and arbitrary question/approval prose remain dynamic/unverified.
- PR/review popup internals, full external-link context menus, artifact-kind icon mappings and global media save/copy menu implementations were not fully inspected; rows flag those limits. Usage window/credit controls were inspected, but all provider-specific formatted reset/pace prose is not reproduced. Routine copy from the earlier inventory is identified with its original snapshot, not incorrectly attributed to current line numbers.
- The requested run_in_background and Monitor tools are not exposed in this pane. Reads ran synchronously with independent reads batched in memory; every invocation completed. No background job was started or remains running.

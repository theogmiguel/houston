# Glossary

Words that collide, and the meaning Houston gives them. Where a term has a home in code, it is
named.

## People and roles

| Term           | Meaning                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **you**        | The coding agent changing Houston. It may itself run inside a pane of the installed release (`HOUSTON_SESSION` is set).                                       |
| **maintainer** | Develops and releases Houston. A maintainer's installed app uses the same protected release channel as any user's install.                                    |
| **user**       | The person running Houston to direct agents. One per install.                                                                                                 |
| **dogfooding** | Running Houston's own development inside Houston. The host scrubs inherited agent markers so a dogfooded host does not leak its identity into what it spawns. |

## Server and state

| Term                                                           | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Code                                                                                                               |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **server**                                                     | The TypeScript server under `apps/server`: the ported codebase's, with Houston's additions under `src/houston/`. The host runs one per channel.                                                                                                                                                                                                                                                                                                                                                                                       | `apps/server`, `apps/desktop/src/backend`                                                                          |
| **host**                                                       | The Electron desktop application. It starts or attaches to its channel's server, bridges the desktop to the renderer, and runs the v1 cleanup at start.                                                                                                                                                                                                                                                                                                                                                                               | `apps/desktop`                                                                                                     |
| **WSL backend**                                                | Windows' optional second Houston environment: a server the host runs inside a WSL 2 distro, with its own channel state, threads, projects and secrets, separate from the Windows server.                                                                                                                                                                                                                                                                                                                                              | `apps/desktop/src/wsl`                                                                                             |
| **channel**                                                    | An isolated state universe: `release` (`~/.houston`), `dev` (`~/.houston-dev`) or a named one (`~/.houston-<name>`).                                                                                                                                                                                                                                                                                                                                                                                                                  | `apps/desktop/src/app/DesktopStatePaths.ts`                                                                        |
| **channel directory**                                          | A channel's directory under the home. v2 writes only its `v2/` child; anything else in it is v1 state.                                                                                                                                                                                                                                                                                                                                                                                                                                | `resolveChannelDir`, `resolveDesktopBaseDir`                                                                       |
| **runtime file**                                               | `<channel dir>/v2/userdata/server-runtime.json`: how the host and other clients find the channel's running server, and the PID a stop uses.                                                                                                                                                                                                                                                                                                                                                                                           | `apps/desktop/src/backend`                                                                                         |
| **thread**                                                     | A structured conversation with one agent. A **turn** is one request and its answer; a **run** is the provider session that serves a thread.                                                                                                                                                                                                                                                                                                                                                                                           | `packages/contracts`                                                                                               |
| **audio destination**                                          | Where this device sends microphone audio: an environment's engine or a cloud provider it forwards to. A per-device grant, Off until chosen; never substituted.                                                                                                                                                                                                                                                                                                                                                                        | `apps/web/src/speech/voiceConsent.ts`                                                                              |
| **cloud dictation key**                                        | A provider API key for cloud dictation, kept in the secret store as `voice-cloud-<provider>` and never returned to clients.                                                                                                                                                                                                                                                                                                                                                                                                           | `apps/server/src/speech/CloudSpeech.ts`                                                                            |
| **project dictionary**                                         | Dictation spellings saved with a project on its environment and merged ahead of each person's own dictionary.                                                                                                                                                                                                                                                                                                                                                                                                                         | `speechProjectCustomWords`                                                                                         |
| **project repositories**                                       | The git repositories a project folder covers: the folder itself when it is a repository, repositories found up to two levels inside it, declared submodules, and folders the user tracked from elsewhere on disk. A thread in the project folder works in all of them; a worktree thread gets a task folder with one worktree per chosen repository.                                                                                                                                                                                  | `apps/server/src/project/repositoryDiscovery.ts`, `apps/server/src/houston/projects/ProjectRepositoriesService.ts` |
| **tracked folder**                                             | A git repository outside a project's folder that is stored with the project, up to 128 per project; the runtime treats it as one of the project's repositories.                                                                                                                                                                                                                                                                                                                                                                       | `apps/server/src/houston/projects/ProjectRepositoriesStore.ts`                                                     |
| **ignored repository**                                         | A discovered repository left out by an ignore pattern from `houston.json` or the project's stored list. The project's own repository and tracked folders are never ignored.                                                                                                                                                                                                                                                                                                                                                           | `apps/server/src/project/repositoryDiscovery.ts`                                                                   |
| **repository key**                                             | A repository's path relative to the project folder, with `/` separators: `.` is the project's own repository and a tracked folder is keyed by its relative path, such as `../name`.                                                                                                                                                                                                                                                                                                                                                   | `apps/server/src/project/threadRepositories.ts`                                                                    |
| **task folder**                                                | The folder a worktree thread of a multi-repository project works in. It mirrors the project layout: each chosen repository is a worktree at the same relative path, every one on the thread's branch name. Its row is keyed by folder path because subagents, forks and reused worktrees share it. Removing it removes the worktrees, leaves the projects' branches, and preserves files that exist only in it. Its checkpoints are one scope for the first repository and a child scope for each other; a rewind restores every one. | `apps/server/src/houston/worktrees/TaskFolders.ts`, `apps/server/src/houston/migrations.ts`                        |
| **side thread**                                                | A read-only thread beside another one (an aside, a second opinion, a task planner or reviewer). It never writes to its source.                                                                                                                                                                                                                                                                                                                                                                                                        | `apps/server/src/houston/sideThreads.ts`                                                                           |
| **provider adapter**                                           | The server's driver for one agent runtime; its structured stream is the only source of agent status.                                                                                                                                                                                                                                                                                                                                                                                                                                  | `apps/server/src/orchestration-v2/Adapters`                                                                        |
| **orchestration**                                              | Agent-to-agent work through orchestration-v2 (`delegate_task`, subagents) and the server's MCP toolkits.                                                                                                                                                                                                                                                                                                                                                                                                                              | `apps/server/src/orchestration-v2`, `apps/server/src/mcp`                                                          |
| **Houston migration track**                                    | Houston's own migration table (`houston_sql_migrations`) and ids, applied after the main track's. Every unrecorded id runs, in ascending order.                                                                                                                                                                                                                                                                                                                                                                                       | `apps/server/src/houston/migrations.ts`                                                                            |
| **layout workspace**                                           | A named, ordered layout the server stores: columns of panes of tabs, with a pin and a hidden flag. Threads of any project share one; a content (a thread's chat, a surface, a page) has one tab across all layout workspaces, and at least one exists. Called "workspace" in the UI and tools; code says `LayoutWorkspace` because `workspace/` is a project's folder.                                                                                                                                                                | `apps/server/src/houston/layoutWorkspaces.ts`                                                                      |
| **workspace**                                                  | The UI and tool name of a layout workspace. A project's folder is a **project**, never a workspace.                                                                                                                                                                                                                                                                                                                                                                                                                                   | `apps/server/src/houston/layoutWorkspaces.ts`                                                                      |
| **column**                                                     | One vertical stack of panes in a workspace's horizontal strip; it has a width, a fraction of the strip, and stays at least 420px wide unless the workspace shrinks to fit.                                                                                                                                                                                                                                                                                                                                                            | `apps/web/src/layout/layoutModel.ts`                                                                               |
| **pane**                                                       | One tabbed area in a column; panes of a column share its height. A pane shows one of its tabs.                                                                                                                                                                                                                                                                                                                                                                                                                                        | `apps/web/src/layout/layoutModel.ts`                                                                               |
| **tab**                                                        | One content in a pane: a thread's chat, a surface, a launcher or a page.                                                                                                                                                                                                                                                                                                                                                                                                                                                              | `apps/web/src/layout/layoutModel.ts`                                                                               |
| **surface**                                                    | One tool a thread works in, such as a diff, files, a file, a browser, a terminal, a pull request or a device. It opens as a tab, linked to its thread but not owned by its chat tab.                                                                                                                                                                                                                                                                                                                                                  | `apps/web/src/layout/surfaceSync.ts`                                                                               |
| **issue**                                                      | A unit of tracker work outside a thread, named by its tracker kind, host, scope and key. The Issues page reads it through the project's tracker; a write is refused outside the project's own scope. A thread keeps the issues it works on as links beside its pull requests.                                                                                                                                                                                                                                                         | `packages/contracts/src/issue.ts`                                                                                  |
| **issue-backed task**                                          | A task backed by exactly one issue: the issue's title names it and a pointer stands in for its text. One issue has at most one unarchived task. Starting, planning or reviewing it links the issue to the thread it launches; with the project's state switch on, its status moves the issue.                                                                                                                                                                                                                                         | `apps/server/src/houston/tasks/TaskService.ts`                                                                     |
| **issue tracker connection**                                   | A standalone tracker reached with the user's own credential, and a project's binding to one of its scopes (a Linear team, a Notion data source). A binding maps the container's properties where the tracker needs it; the Issues page reads the tracker through it.                                                                                                                                                                                                                                                                  | `apps/server/src/issue/IssueTrackerConnections.ts`                                                                 |
| **port forward**                                               | One remote environment loopback port carried to a local `127.0.0.1` port the desktop host listens on. SSH environments use the SSH connection; linked environments use the authenticated tunnel endpoint, which dials the service on the environment. Nothing is forwarded without a user action, and the Settings switch stops every forward.                                                                                                                                                                                        | `apps/desktop/src/portForwarding`, `apps/server/src/houston/portForwarding`                                        |
| **secret store**                                               | The server's directory of secrets: one 0600 file per secret in a 0700 `secrets` directory under the channel's state. Houston's tokens live there; the OS keychain is only read once, to import earlier builds' tokens.                                                                                                                                                                                                                                                                                                                | `apps/server/src/houston/secrets`                                                                                  |
| **linked provider instance**                                   | A provider instance whose `inferenceServerId` names a registered model server. It counts as local exactly while that server is enabled; a removed, disabled or not-ready server makes the instance wait, never fall back to the cloud. Pi, OpenCode, Codex and Claude route through the gateway; other drivers refuse the link by name.                                                                                                                                                                                               | `packages/contracts/src/providerInstance.ts`                                                                       |
| **lean tool profile**                                          | The Pi MCP catalog that advertises only Houston's orchestration, thread, project, worktree, secret and scheduling tools; the default for a Pi instance linked to an inference server. It also omits the preview guidance for tools it leaves out.                                                                                                                                                                                                                                                                                     | `packages/provider-core/src/server/mcpToolProfile.ts`                                                              |
| **local model setup**                                          | The one-step "Use a local model" flow: discover a server, register or reuse it, link Pi or OpenCode, mark the instance local, and set the default for new threads. Each write is an ordinary settings entry.                                                                                                                                                                                                                                                                                                                          | `apps/web/src/components/settings/localModelSetup.logic.ts`                                                        |
| **inference server repair**                                    | Moving a registered server to another address on its host while keeping its id, key and linked agents; the change is made by editing the server's base URL.                                                                                                                                                                                                                                                                                                                                                                           | `apps/web/src/components/settings/FindInferenceServerDialog.tsx`                                                   |
| **model no longer served**                                     | A checked, ready server not listing the model a thread or the default uses; the notice names the model and what the server serves now.                                                                                                                                                                                                                                                                                                                                                                                                | `apps/web/src/state/inferencePresentation.ts`                                                                      |
| **local agent suggestion**                                     | A server-recorded suggestion to turn on Pi or OpenCode found on `PATH`, with remembered dismiss and configured states; Houston never switches an agent on by itself.                                                                                                                                                                                                                                                                                                                                                                  | `apps/server/src/houston/providerSuggestions.ts`                                                                   |
| **Local compute**                                              | Gateway-measured local model work on the Usage page, grouped by server and model with requests, failures, tokens, cached share and latency percentiles. It is never priced as cloud spend.                                                                                                                                                                                                                                                                                                                                            | `apps/web/src/components/usage/UsageLocalCompute.tsx`                                                              |
| **inference gateway**                                          | The server route `/inference/<serverId>/v1` that forwards the OpenAI and Anthropic generation APIs to a registered model server, authenticated by its own bearer credential.                                                                                                                                                                                                                                                                                                                                                          | `apps/server/src/houston/inference`                                                                                |
| **gateway credential**                                         | A bearer token minted per provider session (bound to an instance, thread and server) or per background scope; MCP, OAuth and session tokens never resolve there.                                                                                                                                                                                                                                                                                                                                                                      | `apps/server/src/houston/inference/InferenceGatewayCredentials.ts`                                                 |
| **Codex model catalog**                                        | A JSON file of the linked server's models, their context windows and reasoning efforts, named by content and passed to Codex as `model_catalog_json` when its version reads one. Older Codex versions get the smallest served window instead.                                                                                                                                                                                                                                                                                         | `apps/server/src/houston/inference/codexGateway.ts`                                                                |
| **Claude gateway session**                                     | A Claude Agent SDK session whose `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` point at Houston's gateway for one thread; neither value is written to Claude's home or settings.                                                                                                                                                                                                                                                                                                                                                    | `apps/server/src/houston/inference/claudeGateway.ts`                                                               |
| **admission queue**                                            | One per model server: active and waiting gateway requests, chat before scheduled before background with 30-second aging, a 64-request bound and a 10-minute wait bound.                                                                                                                                                                                                                                                                                                                                                               | `apps/server/src/houston/inference/InferenceAdmission.ts`                                                          |
| **inference watchdog**                                         | The gateway’s per-reply check that stops a looping, reasoning-only or silent reply with the protocol’s own error, and refuses the same run’s retry for a minute.                                                                                                                                                                                                                                                                                                                                                                      | `apps/server/src/houston/inference/InferenceWatchdog.ts`                                                           |
| **prompt cache health**                                        | A server’s reported prompt-cache budget, retained bytes and states, with the cached share of prompt tokens between probes; `saturated-falling` means full while the share dropped.                                                                                                                                                                                                                                                                                                                                                    | `apps/server/src/houston/inference/InferenceServerRegistry.ts`                                                     |
| **pending device**                                             | A paired device waiting for its host owner's approval. It holds no scope, every request and WebSocket method is refused with the pending message, and it expires after 24 hours. Approving copies only the pairing grant's scopes.                                                                                                                                                                                                                                                                                                    | `apps/server/src/auth/SessionStore.ts`, `packages/contracts/src/houston/access.ts`                                 |
| **linked environment**                                         | Another machine this environment holds a link to, distinct from an environment connected to this device. A link carries its own access and token; agents here reach it through the link, and it never shares this environment's database.                                                                                                                                                                                                                                                                                             | `apps/server/src/peer/PeerLinks.ts`                                                                                |
| **linked search**                                              | A command palette search that also asks each linked machine for matching threads, one request per machine carrying only the typed query and a per-machine match limit. Local results never wait for it, and no request is made while the beta is off.                                                                                                                                                                                                                                                                                 | `apps/server/src/houston/peerLinkSearch.ts`, `apps/web/src/state/queries.ts`                                       |
| **client pairing code**                                        | A one-time credential a linked machine issues so this window can connect to that machine as an environment. Only a full-access link may ask; it lives three minutes and carries the intersection of this window's scopes with the scopes a paired client may hold. It appears only in the pairing result.                                                                                                                                                                                                                             | `apps/server/src/houston/peerLinkPairing.ts`                                                                       |
| **v1 state**                                                   | What a v1 install left directly under a channel directory (`houston.db`, scrollback, `bin/claude-hook` and the daemon's discovery files). Read-only to v2; only the Tasks, issue and Slack imports read `houston.db`.                                                                                                                                                                                                                                                                                                                 | `apps/server/src/houston/*/V1Import.ts`                                                                            |
| **v1 cleanup**                                                 | The host's start-up removal of its own channel's v1 hook entries, and of the MCP entries every channel shares while no other channel's v1 daemon runs, from the agent CLI configs. It stands down while that channel's v1 daemon runs.                                                                                                                                                                                                                                                                                                | `apps/desktop/src/app/DesktopV1Cleanup.ts`                                                                         |
| **managed marker**                                             | The `--houston-managed[=<channel>]` token on every entry Houston wrote into an agent CLI's config, matched per token, never as a substring.                                                                                                                                                                                                                                                                                                                                                                                           | `apps/desktop/native/houston-v1-cleanup/src/v1_cleanup`                                                            |
| **task source**                                                | A way a task is filed besides the backlog: Slack intake. Issue trackers are not task sources; a task is created from an issue.                                                                                                                                                                                                                                                                                                                                                                                                        | `apps/server/src/houston/slack`                                                                                    |
| **remote transport policy**                                    | `remoteTransportPolicy`: `any` accepts every route; `private-e2ee-only` refuses tunnel, proxy and plain-LAN WebSocket upgrades and authenticated HTTP before authentication, while loopback and Tailscale always pass. Default `any`; reversible from a connected session or `settings.json`.                                                                                                                                                                                                                                         | `apps/server/src/auth/transportSecurity.ts`                                                                        |
| **E2EE identity key**                                          | The server's long-lived Ed25519 seed for the WebSocket handshake, stored only in the secret store as `e2ee-identity-seed-v1`. Its public key travels as `pk` in pairing links made while E2EE is on; its `XXXX-XXXX-XXXX-XXXX` fingerprint is what a person verifies. Delete the secret and restart to rotate.                                                                                                                                                                                                                        | `apps/server/src/auth/ServerE2eeIdentity.ts`                                                                       |
| **E2EE record**                                                | One encrypted WebSocket frame: `[version][monotonic counter][XChaCha20-Poly1305 ciphertext+tag]`, keyed per direction by HKDF-SHA256 over an ephemeral X25519 secret and the signed transcript. A frame over the part size is split before encryption. Tampering, replay, reordering and plaintext injection fail the socket.                                                                                                                                                                                                         | `packages/shared/src/socketE2ee.ts`                                                                                |
| **connection security badge**                                  | How an environment row names its active session's protection: Local, E2EE (Tailscale / SSH), E2EE, TLS only, or Unencrypted. The app-layer E2EE badge wins over the transport one.                                                                                                                                                                                                                                                                                                                                                    | `packages/client-runtime/src/connection/presentation.ts`                                                           |

## Engineering nouns

| Term               | Meaning                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| **safety scripts** | The hermetic `scripts/check-*.sh` steps the `static` CI job runs on every push.                                              |
| **oom-shield**     | `scripts/oom-shield.sh`: a memory-capped, niced, serialized scope for heavy builds.                                          |
| **gate**           | The verification set for a cadence: focused checks while iterating, full checks at integration boundaries and before a push. |
| **discriminator**  | The specific re-run that distinguishes a known flaky shape from a real failure.                                              |

## Retired terms

| Term     | Replaced by                                                                                                                                                                                                            |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **grid** | **workspace**. A grid belonged to one project and held up to six threads; a workspace holds columns of panes of tabs for any project. `houston_grid_*` tools, the `grid` launch target and `gridId` remain as aliases. |
| **cell** | **pane**.                                                                                                                                                                                                              |
